### 🔍 아키텍처 설명

- 엔진의 기본 구조는 **스레드 간 동기화**를 고려하여 설계되었습니다.  
  IO 작업(텍스처/메시 로딩 등)이나 무거운 계산은 **메인 스레드 이전에 비동기 스레드에서 선처리**되며,  
  최종적인 반영은 메인 스레드에서 수행됩니다.

- 각각의 작업 전용 스레드는 **작업 요청 큐**를 받고,  
  작업을 처리한 후 **Command 객체로 결과를 포장하여 Command 스케줄러에 전달**합니다.

- 현재 구현된 작업 전용 스레드는 다음과 같습니다:
  - 🎨 텍스처 로딩 스레드
  - 🧱 메시 로딩 스레드

- 입력 처리는 **IMGUI 라이브러리 특성상 렌더링 중에만 가능**하기 때문에,  
  **UI 입력 처리와 렌더링은 메인 스레드에서 통합**되어 처리됩니다.  
  만약 서로 다른 스레드에서 처리할 경우, **동기화 지연으로 인한 화면 끊김(race condition)이 발생**할 수 있습니다.

---

### 🧪 물리 엔진 설계 계획

- 향후 **물리 연산 전용 스레드**를 도입할 계획이며,  
  이 경우 **transform 데이터의 경쟁 조건(race condition)** 문제가 빈번하게 발생할 수 있습니다.

- 이를 해결하기 위한 전략으로 **더블 버퍼링(double buffering)** 구조를 사용할 예정입니다:

  - 🧮 **물리 스레드**는 백버퍼(back buffer)에 데이터를 계산하고 기록
  - 🖼️ **메인 스레드**는 프런트 버퍼(front buffer)에서 읽기 전용으로 렌더링에 사용
  - 두 버퍼는 **스왑(swap)**을 통해 안전하게 교체되어 동기화 문제를 방지
